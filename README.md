# 急上昇動画ウォッチャー

YouTube の急上昇ランキングを自動で集めて、**いろいろな切り口のランキング**に並べ直す静的サイトです。

- カテゴリはタブ切り替え（総合・音楽・ゲーム・エンタメ・スポーツ・ニュースなど 15 種）
- ランキングの種類を切り替えられる：**急上昇順 / いま伸びてる順 / 急加速順 / 同時視聴者数順 / 再生数順 / 高評価率順 / コメント数順 / 新着順**
- **ライブ配信中**のタブと、同時視聴者数つきの「いま配信中」モジュール
- 順位の隣に **前回からの変動（▲▼・NEW）** を表示
- サムネイル・再生時間・ショート判定つきの一覧
- 「ランクインの多いチャンネル」ランキングも併載
- 各動画に **直近 12 回分の伸びのミニグラフ**、一覧の上に **前回からの入れ替わり本数と次回更新までの目安**
- **お気に入り（★）・チャンネルのフォロー・ランダムピックアップ・おまかせ順** など、再訪したときに変化が出る仕掛け
- **24 時間前の急上昇**を履歴から復元して見比べられる
- **VTuber 配信ウォッチ（`/vtuber/`）**: ホロライブ・にじさんじ・ぶいすぽっ！などの配信中・配信予定・同接ランキング・登録者数の伸び・誕生日などをまとめた別ページ（後述）
- 収集も公開も GitHub Actions で実行（30 分おき。後述のとおり実際にはもう少し間隔が空きます）

## 必要な準備：YouTube Data API のキー

データは **YouTube Data API v3** から取得します。無料のキーが必要です（審査なし）。

1. https://console.cloud.google.com/ でプロジェクトを作る
2. 「APIとサービス」→「ライブラリ」で **YouTube Data API v3** を有効化する
3. 「認証情報」→「認証情報を作成」→ **APIキー** を発行する
4. ローカルで実行するときは環境変数に入れる

```powershell
$env:YOUTUBE_API_KEY = "発行したAPIキー"
npm run collect
```

GitHub Actions で動かすときは、リポジトリの Secrets に `YOUTUBE_API_KEY` を登録します。

**無料枠は 1 日 10,000 ユニット**です。1 回の収集の内訳は次のとおりです。

| 呼び出し | 回数 | 単価 | 小計 |
| --- | --- | --- | --- |
| `videos.list`（カテゴリ別の急上昇） | 15 | 1 | 15 |
| `search.list`（配信中のライブ探し） | 1 | **100** | 100 |
| `videos.list`（ライブの数値取り直し） | 1 | 1 | 1 |
| `channels.list`（登録者数・アイコン） | 3〜5 | 1 | 5 |
| | | | **約 120** |

30 分に 1 回（1 日 48 回）で約 5,760 ユニット。枠の 6 割ほどです。

ただし **`search.list` だけは 1 回 100 ユニット**と高いので、
`config.json` の `live.queries` / `live.categoryIds` を増やすとそのぶん一気に消費します
（1 要素につき +100 ユニット / 回）。増やすときは 1 日の合計を計算してからにしてください。
ライブ収集自体を止めるなら `live.enabled` を `false` にします。

> キーがなくても `npm run sample` でサンプルデータを作れば、画面の確認だけはできます。
> その場合はページ上部に「これはサンプルデータです」と表示されます。

## 使い方

```bash
npm install          # esbuild / sharp（ビルド用のみ）
npm run sample       # サンプルデータを作る（APIキー不要・画面確認用）
npm run collect      # 実データを収集して docs/data/rankings.json を更新
npm run collect:vtuber  # VTuber の配信を収集して docs/data/vtuber.json を更新（キーなしでも RSS の新着だけは集まる）
npm run roster       # VTuber の名簿を公式サイトから作り直す（普段は collect:vtuber が 1 週間おきに自動で行う）
npm run sample:vtuber   # VTuber のページを確認するためのサンプルデータを作る（配信状況は架空）
npm run build        # site/ を最小化して docs/ に出力
npm start            # ビルドしてローカルサーバー（http://localhost:3240）
```

## 構成

| パス | 役割 |
| --- | --- |
| `config.json` | カテゴリ（タブ）とランキングの種類、収集件数などの設定 |
| `scripts/collect.mjs` | 収集 → 伸び・順位変動の計算 → `docs/data/rankings.json` 出力 |
| `scripts/lib/youtube.mjs` | YouTube Data API（videos.list / channels.list）の呼び出し |

| `data/history.json` | 動画ごとの再生数・順位の推移（直近 24 回分）。**伸びのグラフと「24 時間前の急上昇」に使うのでコミットする** |
| `scripts/collect-vtuber.mjs` | VTuber の収集 → `docs/data/vtuber.json`（ページ用）と `docs/data/vtuber-top.json`（急上昇ページの右カラム用） |
| `scripts/lib/vtuber-roster.mjs` / `scripts/sync-roster.mjs` | 各事務所の公式サイトから名簿（チャンネル ID・誕生日・デビュー日など）を作る |
| `scripts/lib/vtuber.mjs` | RSS の読み取りと、ページに出す集計（同接ランキング・記念日・ゲーム名の抽出・コラボ検出など） |
| `data/vtuber-roster.json` | VTuber の名簿。**コミットする**（公式サイトが読めなかったときは前回の名簿を使い続ける） |
| `data/vtuber-state.json` | 追跡中の配信・同接のピーク・登録者数の日ごとの推移など。**コミットする** |
| `site/` | 編集するソース。`docs/` は生成物なので直接触らない |
| `docs/` | 公開ディレクトリ（FTP でアップロードされる） |

## ランキングのしくみ

1. カテゴリごとに `videos.list?chart=mostPopular&regionCode=JP` で急上昇を取得する
   （複数カテゴリに出る動画はまとめ、良いほうの順位を残す）
2. `data/history.json` の前回値と比べて
   - **いま伸びてる順** … 1 時間あたりの再生数の増加
   - **急加速順** … 直近の伸びが、直前 6 回の伸びの中央値の何倍か（1 時間あたり 3,000 回未満は対象外）
   - **▲▼の順位変動** … 前回の順位との差
   を計算する（初めて見る動画は NEW 扱い。伸びは公開からの平均で代用）
3. `search.list?eventType=live` で配信中のライブを探し、`videos.list` で同時視聴者数を取り直して
   「ライブ配信中」タブに載せる（急上昇にも出ているライブは両方に出る）
4. `channels.list` で登録者数とチャンネルアイコンを足す
5. チャンネル別のランクイン本数を数えてチャンネルランキングを作る
6. すべてを `docs/data/rankings.json` に書き出し、フロントはこの 1 ファイルだけを読む

### 更新されている感を出すしくみ

YouTube の急上昇チャートそのものは**数時間おきにしか入れ替わりません**（2026-09-23 の実測で 1 日 3〜4 回）。
30 分おきに集めても急上昇順は何時間も同じ並びのままなので、集計ごとに変わるものを別に出しています。

- **前回からの動き**（一覧の上の帯）… 伸び 1 位・加速・急上昇入り・配信開始・順位アップを最大 5 本（`moves`）
- **急加速順** … 上位 10 本のうち毎回 6〜9 本が入れ替わる（いま伸びてる順は 1〜3 本）
- 急上昇順の説明文に**YouTube 側で最後に並びが変わった時刻**を出す（`chartChangedAt`。総合の並びを `history.json` の `chartSig` と比べて判定）
- 開いたままのページは 3 分おきに新しい集計を確かめ、あれば「新しいランキングがあります」ボタンを出す

**「いま伸びてる順」は 2 回目の収集から本領を発揮します**（前回値がないと差分が出せないため）。
初回はすべて NEW 扱いになります。

調整したいところ:

- `categories` … タブに出すカテゴリ（`youtubeCategoryId` は YouTube のカテゴリ ID）
- `rankings` … ランキングの種類と説明文
- `maxResults` … 1 カテゴリあたりの取得件数（最大 50）
- `likeRateMinViews` … 高評価率ランキングの対象にする最低再生数（既定 10,000）
- `historyDays` … 履歴を残す日数（既定 3 日）。増やすと history.json が大きくなる
- `samplePoints` / `sparkPoints` … 履歴に残す回数（既定 24）と、グラフに出す点数（既定 12）
- `live.enabled` / `live.queries` / `live.categoryIds` … ライブ配信の収集（クォータ注意、上記参照）

## VTuber 配信ウォッチ（`/vtuber/`）

ホロライブ・にじさんじなどの VTuber の YouTube 配信を、急上昇の収集と同じ 30 分おきに集めて別ページに出しています。

### ページに出しているもの

- **いま配信中**（同時視聴者数・経過時間・ジャンル）と **配信予定**（YouTube に枠が立っているもの。日ごと・あと何分）
- **同時視聴者数ランキング**（24 時間・7 日間。30 分おきに観測した最大値）
- **新着動画・アーカイブ**（新しい順・1 時間あたりの伸び順・再生数順。配信アーカイブ／動画／ショートで絞り込み）
- **コラボ配信**（タイトルにほかのタレントの名前が入っているもの）と **急上昇に入っている VTuber の動画**
- **事務所別の配信状況**・**同時視聴者数の推移（48 時間）**・**配信ジャンルの内訳**（歌枠・雑談・ASMR など、タイトルから分類）
- **いま遊ばれているゲーム・企画**と**話題のハッシュタグ**（タイトルの【】と # から。2 人以上が使っているものだけ）
- **誕生日・デビュー記念日・デビューしたばかりのタレント**（公式プロフィールから）
- **登録者数ランキング**（1 日・7 日・30 日の伸び）と **登録者数の節目**（もうすぐ大台・この 1 週間で到達）
- **タレント名鑑**（配信中・次の配信・最後の配信・ファンネーム・公式プロフィールへのリンク）
- 事務所タブ（`?ag=hololive` のように URL でも指定できる）・検索・**推し登録**（localStorage の `vt:oshi` に保存）

### 名簿の作り方

`config.json` の `vtuber.agencies` に書いた事務所の公式サイトから、**1 週間おきに自動で**作り直します（`data/vtuber-roster.json`）。

| 事務所 | 取り方 | 取れるもの |
| --- | --- | --- |
| ホロライブ（JP・EN・ID・DEV_IS） | 公式のタレント一覧 → 各タレントのページ | チャンネル、ユニット、誕生日、初配信日、ファンネーム |
| にじさんじ（JP・EN） | 公式サイトのデータ（Next.js） | チャンネル、誕生日、デビュー日、ファンネーム、英語名 |
| ホロスターズ・ネオポルテ | 公式のタレント一覧 → 各タレントのページ | チャンネル、誕生日など（載っているものだけ） |
| ぶいすぽっ！・ななしいんく | メンバー一覧のページの YouTube リンク | チャンネルと名前 |

- 【卒業生】【配信活動終了】のタレントは載せません
- 公式サイトの作りが変わって取れなかった事務所や、人数が前回の半分未満になった事務所は、前回の名簿をそのまま使います
- 事務所を足すときは `agencies` に 1 件足します（`source.type` は `pages` / `nijisanji` / `links`）。色はグラフ用の 8 色の並びの続きを使ってください
- 名簿にない個人のチャンネルを追いかけたいときは `extraChannels` に `{ "id": "UC…", "name": "名前" }` を足します
- 名簿にない VTuber も、急上昇・ライブ配信中の一覧にタイトルやチャンネル名に「VTuber」などが入った動画が出てくると「個人勢・その他」として自動で追いかけ始めます（最後に見かけてから 14 日間・最大 120 チャンネル。`keywords` / `excludeKeywords` で調整。切り抜きチャンネルは除外）

### 集め方と API の使用量

1. 名簿の全チャンネル（約 370）の **RSS**（`https://www.youtube.com/feeds/videos.xml?channel_id=…`）を読む。**API のユニットを使わない**。直近 15 本と再生数が取れる
2. 新しく見つけた動画と、配信中・配信予定の枠だけを `videos.list`（50 本で 1 ユニット）で確かめる。予定は開始が近いほど頻繁に、何週間も先のフリーチャットは 1 日 1 回だけ確かめる
3. 登録者数は `channels.list` で 3 時間おきに取り直し、日本時間の日ごとに残して伸びを出す（`channelStatsEveryMin`）
4. RSS が読めなかったチャンネルは `playlistItems.list`（1 チャンネル 1 ユニット、1 回 60 チャンネルまで）で補う

| 呼び出し | 1 回あたり | 1 日あたり（48 回） |
| --- | --- | --- |
| `videos.list`（配信の状態） | 5〜10 | 約 250〜500 |
| `channels.list`（登録者数、3 時間おき） | 8 | 約 64 |
| `playlistItems.list`（RSS が読めなかったときだけ） | 0（最大 60） | 普段は 0 |
| 名簿の作り直し（ハンドル → チャンネル ID、週 1 回・新しい人の分だけ） | — | ほぼ 0 |

初回だけは、RSS で見つかった直近 10 日分（約 1,000〜1,500 本）を確かめるので 30 ユニットほど使います。
急上昇の収集（1 日約 5,760）と合わせても 1 日 6,500 ユニット前後で、無料枠（10,000）に収まります。

キーがないとき（手元で `npm run collect:vtuber` したときなど）は、RSS で分かる新着動画だけを更新し、配信中・配信予定は前回の値のままにします。

`config.json` の `vtuber` で調整できるもの:

- `enabled` … `false` にすると VTuber の収集を止める
- `rosterMaxAgeDays` … 名簿を作り直す間隔（既定 7 日）
- `checkWindowDays` … RSS で見つけた動画のうち、状態を確かめる範囲（既定 10 日以内に公開されたもの）
- `keepDays` … 終わった配信・動画を追いかける日数（既定 3 日。同接ランキングの 7 日分は別に残す）
- `upcomingDays` … 配信予定に出す範囲（既定 7 日）
- `maxCheckPerRun` … 1 回に `videos.list` で確かめる本数の上限（既定 1,500 本 = 30 ユニット）
- `rssFallbackMax` … RSS が読めなかったときに API で補うチャンネル数の上限（既定 60）

## 更新の間隔について（実際はどのくらい空くか）

狙いは **30 分おきの更新**ですが、**cron を 30 分おきに書いてもそうはなりません**。GitHub Actions のスケジュール実行はベストエフォートで、混雑していると遅れるどころか配信されないことがあります。

2026-09-16 の実測では、cron の書き方を変えても**実際に走るのは約 3 時間に 1 回**でした。

| cron | 結果 |
| --- | --- |
| `"0 * * * *"`（毎時 0 分） | 12 回中 4 回だけ実行。遅れは 3 分〜54 分 |
| `"7,37 * * * *"`（混雑時刻を避けて 30 分おき） | 5 時間まったく実行されず |

同じアカウントの aimatome でも同じ傾向だったので、cron の書き方の問題ではありません。

10 分おきに起動して密度で補おうともしましたが、**9 スロット連続で 1 回も配信されませんでした**（trend-video-watcher と aimatome の両方で同時に確認）。**cron 側でできることはありません。**

一方 `workflow_dispatch` と `repository_dispatch`（どちらも外から叩く経路）は**一度も失敗していません**。そこで、更新の主役は外部トリガーにしています。

### 外部から 30 分おきに叩く（推奨・実質これが本番の更新経路）

ロリポップの cron から `tools/trigger-collect.php` を実行します。このスクリプトは trend-video-watcher と aimatome の両方に `repository_dispatch` を送るので、**サーバー上に 1 つ置けば両サイトが更新されます**。

1. GitHub で **fine-grained personal access token** を作る
   - Repository access: 対象のリポジトリだけ
   - Permissions: **Contents = Read and write**（`repository_dispatch` に必要なのはこれだけ）
   - 有効期限を必ず設定する
2. ロリポップの**公開ディレクトリの外**に `tools/trigger-collect.php` を置き、同じ場所に `token.txt`（トークンを 1 行、パーミッション 600）を作る
   - 公開ディレクトリに置くと誰でも叩けてしまう
   - `token.txt` は `.gitignore` 済み。**リポジトリには絶対に入れない**
3. ユーザー専用ページ → cron 設定で 30 分おきに実行する
   - 例: `/usr/local/bin/php /home/users/0/xxxx/tools/trigger-collect.php`

手元から 1 回だけ叩いて確かめることもできます（`<TOKEN>` は自分のトークンに置き換え）。

```bash
curl -X POST -H "Accept: application/vnd.github+json" -H "Authorization: Bearer <TOKEN>" \
  https://api.github.com/repos/lumieregiurare-ops/trend-video-watcher/dispatches \
  -d '{"event_type":"collect"}'
```

成功すると **204 No Content** が返り、Actions に `repository_dispatch` の実行が現れます。

### cron はフォールバックとして残してある

配信されたときのために 10 分おきの cron も残しています。外部トリガーと二重に走らないよう、**前回の収集から 25 分たっていなければ即座に終了する**ガードを入れてあります（`collect.yml` の「前回からの経過時間を見る」ステップ。前回の時刻は `data/history.json` の `ranAt`）。空振りの回は 15 秒ほどで終わり、YouTube API のユニットも消費しません。手動実行（Actions タブの Run workflow）だけは間隔に関係なく必ず収集します。

**この密な cron は公開リポジトリ（Actions の実行時間が無制限）を前提にしています。** 非公開に戻す場合は、1 日 144 回の起動が無料枠 2,000 分を圧迫するので見直してください。

そのため、サイトに出す「次の更新まで約 ○ 分」は cron の設定値から計算せず、**実際に走った間隔の中央値**から出しています（`data/history.json` の `runs` に直近の実行時刻を残し、`collect.mjs` で中央値を取って `rankings.json` の `updateGapMin` / `nextUpdateAt` に書き出す）。目安の時刻を過ぎたら「まもなく更新されます」と言い続けず、「最終更新 ○ 分前」に切り替わります。設定どおりの時刻を出すと、カウントダウンが 0 のまま何時間も止まって、更新が終わったサイトのように見えてしまうためです。

確実に 30 分おきで回したい場合は、外部からワークフローを叩く方法があります（例: cron-job.org などの無料の定期実行サービスから `repository_dispatch` を POST する。PC を起動しておく必要はありませんが、リポジトリへの書き込み権限を持つトークンを外部サービスに預けることになります）。

## ブラウザに保存しているもの

お気に入りなどは **localStorage にだけ**保存しています。サーバーには何も送りません。

| キー | 中身 |
| --- | --- |
| `ytg:favs` | お気に入りの動画。急上昇から外れると収集データから消えるため、見出し・サムネイル・保存時の再生数も一緒に控えている（「保存してから +◯回」の表示に使う） |
| `ytg:follows` | フォローしたチャンネル |
| `ytg:seen` | 開いた動画の ID（最大 400 件）。ピックアップで同じ動画を出さないために使う |
| `ytg:state` | 選んでいるカテゴリ・並び順などの画面の状態 |
| `vt:oshi` | VTuber のページで「推し」に登録したチャンネル |
| `vt:state` | VTuber のページで選んでいる事務所・並び順などの画面の状態 |

ブラウザのデータを消すと失われるため、お気に入りタブに書き出し／読み込みのボタンを置いています。

## 履歴ファイルの大きさ

`data/history.json` は動画 700 件・24 回分で **900KB 程度**になります。
30 分おきにコミットするので、増えすぎるようなら `historyDays` か `samplePoints` を減らしてください。

## 表示している内容について

タイトル・サムネイル・公開されている数値（再生数・高評価数・コメント数・登録者数）と、
YouTube へのリンクのみを表示しています。動画のダウンロードや再配布はしていません。
サムネイルは YouTube の画像 URL をそのまま参照しています。
